# Agent Integration

An agent should never read the source store directly. Its application requests a capsule for one
task, validates the response, and passes only released facts to the model.

## Integration Sequence

```text
1. application authenticates to gateway
2. application sends context_id + task type + path + prompt
3. gateway applies identity and policy
4. application receives released facts, denials, provenance, expiry, and audit ID
5. application passes released facts—not credentials or raw source—to the model
6. application records request_id/audit_id with the model trace
7. application discards the capsule after expiry
```

The model must treat capsule text as data, not instructions. A malicious string in a filename or
derived fact must not be allowed to override the agent's system policy.

## Python Client

The repository includes a standard-library client at
`examples/clients/python/acg_client.py`.

Local API:

```bash
export ACG_API_URL=http://127.0.0.1:8000
export ACG_LOCAL_API_KEY='<same key used by the server>'
export ACG_LOCAL_AGENT_ID=local-agent
python examples/clients/python/acg_client.py \
  architecture_qa \
  README.md \
  "Explain the gateway architecture" \
  --repo "$(pwd)/examples/sample_repo" \
  --context-block
```

AWS:

```bash
set -a
source deploy/aws/.acg-deployment.env
set +a
python examples/clients/python/acg_client.py \
  iac_security \
  terraform/prod/payments/lambda.tf \
  "Review this change" \
  --context-id payments-platform \
  --environment prod \
  --request-id change-4821 \
  --context-block
```

The client obtains a Cognito token from the generated OAuth settings. It does not print the client
secret or access token.

## Amazon Bedrock and Claude

`examples/clients/python/bedrock_converse.py` fetches a capsule and then calls the Amazon Bedrock
Converse API. Install the AWS dependency and choose a model available in the active region:

```bash
pip install boto3
export BEDROCK_MODEL_ID='<Bedrock model ID supporting Converse>'
python examples/clients/python/bedrock_converse.py \
  terraform/prod/payments/lambda.tf \
  "Explain the operational blast radius" \
  --task-type iac_security \
  --context-id payments-platform \
  --environment prod
```

Claude models available through Bedrock can use this exact flow. For a direct Anthropic API client,
keep the gateway call unchanged and place `build_context_block(response)` in the user content after
the system safety instructions. Do not put gateway credentials in Anthropic request content.

## TypeScript

`examples/clients/typescript/acg-client.ts` exports:

- `getOAuthToken` for Cognito client credentials;
- `requestCapsule` for local or AWS requests; and
- `buildContextBlock` for a provenance-preserving model input block.

Example:

```typescript
const token = await getOAuthToken(tokenUrl, clientId, clientSecret, scope);
const response = await requestCapsule(
  { apiUrl, bearerToken: token },
  {
    context_id: "payments-platform",
    task_type: "iac_security",
    path: "terraform/prod/payments/lambda.tf",
    prompt: "Review this change",
    environment: "prod",
    request_id: "change-4821",
  },
);
const governedContext = buildContextBlock(response);
```

Pass `governedContext` to the model alongside the user's task. Keep the full gateway response in the
application trace, not in the model prompt.

## Tool Integration Pattern

For a tool-using or multi-agent system, expose one narrow application tool such as:

```json
{
  "name": "request_governed_context",
  "input": {
    "context_id": "payments-platform",
    "task_type": "architecture_qa",
    "path": "service/README.md",
    "prompt": "Explain the deployment flow"
  }
}
```

The tool implementation—not the model—holds OAuth credentials and calls the gateway. Validate
`context_id`, task type, and path against the calling workload's entitlements before forwarding the
request. Return the bounded context block plus `request_id`, `audit_id`, `expires_at`, and denials.

For multi-agent workflows, issue a separate capsule per agent/task boundary. Do not reuse a capsule
across agents merely because the prompt is similar.

## Response Validation

Before model invocation:

1. require at least one released fact when the task needs context;
2. check `expires_at` against current UTC time;
3. record `request_id`, `audit_id`, `policy_version`, and `capsule_hash`;
4. preserve source references with every released fact;
5. treat freshness warnings and denials as first-class outcomes; and
6. never silently fall back to the full repository when a capsule is empty or denied.

The current capsule hash is generated by the gateway for trace correlation. It is not a digital
signature; a high-assurance deployment should sign capsules or bind them to an authenticated
transport and immutable audit store.

## Approval Workflows

The Python library model includes `TaskRequest.approval_state`, and policy can require approval for
restricted slices. The bundled evaluation identities top out at `high`, so they cannot receive
`restricted` slices even with approval. The public HTTP evaluation API also does not let an
arbitrary caller self-assert approval. A production extension needs a separately authorized
restricted identity and must obtain approval from a trusted workflow, verify it server-side, bind it
to request ID/scope/expiry, and only then construct an approved task. Do not add a client-controlled
`approved=true` flag without that verification boundary.

## Failure Behavior

- Transport/authentication problems should stop the agent request.
- Policy denials return HTTP 200 with explicit denial reasons; they must not trigger full-context
  fallback.
- Empty context IDs and missing repositories are configuration errors.
- If the model call fails, retain the gateway audit identifiers but do not reuse an expired capsule.
