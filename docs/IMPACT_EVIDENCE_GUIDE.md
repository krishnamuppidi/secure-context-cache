# Adoption and Impact Evidence Guide

Website traffic can help people discover Secure Context Cache, but raw visits are weak evidence of
technical adoption. The useful chain is:

**qualified discovery → reproducible evaluation → GitHub or deployment activity → independent use
or pilot → documented result**

## Preserve Monthly Evidence

Export and date-stamp:

- Google Search Console queries, pages, countries, clicks, impressions, and average position.
- GitHub traffic, clones, unique cloners, referring sites, release downloads, contributors, forks,
  discussions, and issues.
- Package or container downloads when the source offers verifiable statistics.
- Citations, external technical references, conference material, and independent articles.
- Pilot scope, baseline, quality gates, raw provider usage, failures, and evaluator confirmation.

Keep raw exports and a short methodology note. Screenshots alone are harder to reproduce.

## Prioritize Qualified Actions

The website should route engineers to actions that demonstrate technical interest:

- Run the deterministic demo.
- Download and use the secure RAG review checklist.
- Open an external evaluation issue.
- Reproduce the benchmark.
- Complete the pilot template.
- Cite the software or publish an independent integration.

Optional analytics must remain consent-based and aggregate. Do not send names, email addresses,
form contents, credentials, or full outbound URLs to analytics.

## Evidence Boundaries

- Label project-controlled tests, independent evaluations, and production use separately.
- Report token reduction only alongside accepted-result quality and prohibited-release results.
- Preserve failures and limitations, not only favorable averages.
- Do not buy traffic, backlinks, stars, forks, downloads, testimonials, or citations.
- Never imply that a company, evaluator, or standards body endorses the project without permission.

This guide supports honest technical documentation. It is not legal or immigration advice.
