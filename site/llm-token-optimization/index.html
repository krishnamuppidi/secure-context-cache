Why token cost grows

Enterprise prompts repeat far more than the task changes.

Repositories, policies, runbooks, service maps, and prior decisions are often resent for every request.

The hidden cost is repeated context, not only the user prompt.

An enterprise agent may need a few changed files but receive an entire repository, architecture guide, security policy, and operational history. The model processes that material again for every review. Larger prompts can increase input cost and latency while exposing facts the current task never needed.

Simple truncation is not a safe answer. A smaller prompt that misses a required control, dependency, or exception can produce a cheaper but unacceptable result. The optimization target therefore has two parts: reduce context and preserve the facts required by the task's quality gate.

North-star metric: cost per accepted, correct, policy-compliant result.

Do not count a token reduction as savings when it causes the optimized run to fail the agreed quality threshold.

Benchmark design

Compare the same work through three context paths.

A paired evaluation separates token savings from task difficulty and model variation.

A defensible LLM token-optimization test

Use the same task set, model, settings, and acceptance rubric for each path. The changed-files-only path tests minimal context. The full-context path establishes the quality and cost baseline. The Secure Context Cache path tests whether a governed capsule can retain quality with fewer input tokens.

Use provider-reported usage for production claims

The repository includes a deterministic fixture that demonstrates the metric flow. It is not a universal production benchmark. A real pilot should preserve raw provider usage, pricing assumptions, task identifiers, quality scores, and reviewer decisions.
