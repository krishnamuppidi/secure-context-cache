A practical benchmark for agent context quality

Infrastructure-as-Code changes are structured, versioned, and tied to reviewable outcomes. Teams can define must-find risks such as public exposure, permissive identities, missing encryption, unsafe network rules, privileged containers, or environment-specific control violations.

The hard part is context. Changed files may omit a shared module, policy exception, service owner, or environment rule. Full repository context can be costly and overbroad. A governed capsule aims to include the dependencies and controls required for the review without exposing unrelated repository knowledge.

Run paired reviews

Adjudicate findings

Record must-find recall, precision, false positives, acceptance, tokens, cost, and latency.

Do not optimize only for shorter prompts.

The relevant outcome is whether the smaller governed capsule preserves or improves accepted security findings at lower provider-reported input cost.

Separate prototype results from pilot results

Controlled prototype measurements demonstrate the framework's evaluation approach. They do not establish a universal outcome for every repository, model, organization, or policy. A pilot should use the organization's task set and preserve the raw provider, reviewer, and gateway evidence behind its claims.
